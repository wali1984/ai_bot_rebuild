## ROOT CAUSE

In `data_loader.py::_label_from_closed_trade_outcome`:
```python
value = float(matched[-1]["realized_pnl_bps"])
return float(max(-250.0, min(250.0, value)))
```

Then in `_label_action`:
```python
if expected_move_after_cost_bps >= 4.0:
    return 1  # LONG
if expected_move_after_cost_bps <= -4.0:
    return 2  # SHORT
return 0
```

**Problem:** `realized_pnl_bps` is POSITION PnL (positive = trade made money). For a SHORT trade where price went DOWN (SHORT wins), `realized_pnl_bps > 0` → labeled LONG. But price going DOWN means the SHORT signal was correct → should be labeled SHORT.

**The `action` field** in the feedback row correctly stores 'short' or 'long' but is NOT used for label computation.

## MINIMAL FIX

**Option A (Correct approach — use price direction):**
```python
def _label_from_closed_trade_outcome(self, *, payloads, tensor):
    # ... existing matching code ...
    if not matched:
        return None
    row = matched[-1]
    raw_pnl_bps = float(row.get("realized_pnl_bps") or 0)
    
    # FIX: Correct for trade direction — convert position PnL to price direction
    action = row.get("action") or row.get("side") or ""
    if action == "short":
        # For SHORT: positive PnL = price went DOWN = SHORT signal = negative expected move
        # (expected_move is from LONG perspective: negative = short opportunity)
        direction_corrected_bps = -raw_pnl_bps
    else:
        # For LONG: positive PnL = price went UP = LONG signal = positive expected move
        direction_corrected_bps = raw_pnl_bps
    
    return float(max(-250.0, min(250.0, direction_corrected_bps)))
```

**Option B (Alternative — use price move directly):**
Use `(exit_price - entry_price) / entry_price * 10000` as the direction signal (price move bps, not PnL bps). This is independent of position direction and directly encodes price movement.
