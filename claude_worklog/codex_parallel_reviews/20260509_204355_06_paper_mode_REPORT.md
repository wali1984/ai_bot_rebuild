## Concrete Blockers

1. Risk gateway does not require paper-mode evidence before emitting `allow`.
   - Non-live autofix: extend `assemble_risk_decision_record` and `build_risk_decision_evaluator` with a keyword-only `paper_mode_flag: PaperModeFlag`.
   - Reject or deterministically deny before `allow` when the flag is missing, not a `PaperModeFlag`, has `live_blocked != True`, has an unsupported mode, or violates an explicit deterministic freshness/window policy.
   - Add unit tests proving open-long/open-short cannot become `allow` without valid paper-mode evidence.

2. Paper ledger does not require or preserve paper-mode evidence.
   - Non-live autofix: extend ledger assembly/composition to require `paper_mode_flag: PaperModeFlag`.
   - Preserve `paper_mode` and `paper_mode_flag_emitted_ts_ms` in `PaperExecutionLedgerEntry` or a typed ledger evidence envelope.
   - Add tests proving ledger recording rejects missing/invalid paper-mode evidence and preserves mode/timestamp on every row.

3. End-to-end paper path is harness-adjacent, not enforced.
   - Non-live autofix: add a deterministic local-only integration harness composing `paper_mode -> orchestrator_decision -> risk_gateway -> paper_execution_ledger -> replay/explainability`.
   - Include negative cases for missing flag, `live_blocked=False`, unrecognized mode, stale/mismatched flag timestamp, and valid flag success.
   - Keep it pure: no Redis, no exchange adapters, no live services, no HTTP, no file persistence.

4. Explainability lacks ledger/replay-level runtime mode evidence.
   - Non-live autofix: project paper-mode mode, flag timestamp, and live-blocked posture into the ledger/replay/explainability evidence that operators inspect.
   - Add tests proving every risk-approved and paper-ledger-visible row can explain the runtime mode used at decision time.
