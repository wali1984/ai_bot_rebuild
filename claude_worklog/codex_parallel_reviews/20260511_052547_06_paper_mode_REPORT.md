## Findings

### Pass: paper-mode flag composition is pure and rejects live-enable modes

The paper-mode runtime is a narrow binder: `build_paper_mode_runtime` validates only the injected clock, captures it, and returns a slotted `PaperModeRuntime` with one keyword-only `paper_mode_now` closure. The closure delegates to `assemble_paper_mode_flag` and returns the typed `PaperModeFlag`; see `v2/backend/app/composition/paper_mode/runtime.py:21-39`.

The service accepts only `paper` and `live_blocked`, rejects non-strings and unrecognized modes, calls the injected clock once, and constructs the flag with `live_blocked=True`; see `v2/backend/app/services/paper_mode/service.py:13-45`. The domain flag rejects unknown modes, bad timestamps, and any `live_blocked` value other than `True`; see `v2/backend/app/domain/paper_mode/flag.py:10-48`.

### Pass: no live execution path found in the inspected paper-mode surface

The inspected paper-mode runtime/service/domain code does not import exchange adapters, Redis, FastAPI routers, environment readers, background tasks, or persistence. Related composition roots for risk and paper ledger are also pure clock-bound assemblers, not execution adapters.

No order-placement, leverage/margin mutation, live-service restart, Redis write, or deployment path was exercised or found in the inspected implementation.

### Blocker 1: risk gateway does not consume the paper-mode flag as an enforcement input

`assemble_risk_decision_record` accepts only `decision` and `now_ms_clock`; it never accepts or validates a `PaperModeFlag`. It sets `live_blocked=True` internally on the returned risk decision at `v2/backend/app/services/risk_gateway/service.py:25-79`.

That means the risk gateway cannot currently deny because the paper-mode flag is missing, stale, false, or mismatched. The `RiskDecisionRecord` domain enforces that its own `live_blocked` field is true, but that is not the same as proving a current paper-mode runtime flag was present at the gateway boundary.

### Blocker 2: paper ledger integration does not consume the paper-mode flag

`assemble_paper_execution_ledger_entry` accepts only a `RiskDecisionRecord` and a clock, then writes `live_blocked=True` internally on the ledger entry; see `v2/backend/app/services/paper_execution_ledger/service.py:26-93`.

The paper-mode evidence harness creates a `PaperModeFlag` and separately replays prebuilt ledger entries into replay steps, but the flag is not passed into ledger recording or replay step assembly; see `v2/backend/tests/unit/paper_mode_evidence_collection_harness/harness.py:37-53`.

This proves coexistence of flag + ledger + replay records, but not an enforced paper-mode-to-ledger integration.

### Blocker 3: decision explainability projects paper mode only in a harness, not from risk/ledger records

The decision explainability data-contract harness creates a fresh paper-mode flag and copies `paper_mode_live_blocked` and `paper_mode_mode` into envelopes at `v2/backend/tests/unit/decision_explainability_data_contract/harness.py:43-80`.

The paper ledger explainability projection does not include paper-mode fields at all; it projects ledger fields only at `v2/backend/tests/unit/decision_explainability_paper_ledger_projection/harness.py:15-81`.

This gives useful test coverage for a synthetic explainability envelope, but the production domain records do not carry a runtime flag ID, flag timestamp, or mode field through risk and paper ledger outputs. A consumer cannot explain which specific paper-mode flag authorized or constrained a given risk decision or ledger entry.

## Proposed Non-Live Autofix Tasks

1. Extend the pure risk-gateway assembler boundary to require `paper_mode_flag: PaperModeFlag`. Deny or raise a service error when the flag is absent, not a `PaperModeFlag`, not `live_blocked=True`, or not in the allowed paper/live-blocked modes. Keep the function pure and clock-injected; do not add Redis, exchange adapters, API routes, or persistence.

2. Add risk-gateway tests proving `paper` and `live_blocked` flags allow the existing allow/deny mapping, while missing/invalid/stale/false live-blocked evidence blocks before an allow risk decision can be emitted.

3. Extend the paper execution ledger assembler boundary to require the same `PaperModeFlag` or a risk record that already carries paper-mode evidence, and propagate `paper_mode_mode`, `paper_mode_live_blocked`, and `paper_mode_flag_emitted_ts_ms` into typed ledger or explainability projection fields.

4. Add end-to-end non-live composition tests for prediction -> orchestrator decision -> paper-mode flag -> risk gateway -> paper ledger -> explainability envelope. Use deterministic in-memory fixtures only.

5. Update decision explainability projections so risk and paper-ledger explainability both derive paper-mode fields from the records assembled on the path, not from a standalone harness flag created beside them.

6. Add negative safety tests proving none of the new flag enforcement paths import Redis, exchange clients, environment live toggles, order methods, leverage/margin methods, schedulers, or FastAPI live routes.

## Decision

The inspected implementation is non-live and the standalone paper-mode flag is correctly constrained, but the Paper Mode MVP is not ready because the runtime flag is not an enforcement input to the risk gateway or paper ledger, and explainability does not carry paper-mode evidence from the actual risk/ledger records. Keep blocked until those integrations are added with pure, non-live tests.
