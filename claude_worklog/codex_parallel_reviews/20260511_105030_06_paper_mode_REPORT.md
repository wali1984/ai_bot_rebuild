## Findings

### Pass: paper mode flag composition is narrow and fail-closed

`PaperModeFlag` accepts only `paper` and `live_blocked`, rejects unknown modes, rejects bad timestamps, and requires `live_blocked is True` in `v2/backend/app/domain/paper_mode/flag.py`.

The service/composition path preserves that boundary:
- `v2/backend/app/services/paper_mode/service.py:16` accepts `requested_mode` and a clock only.
- `v2/backend/app/services/paper_mode/service.py:25` rejects unrecognized requested modes.
- `v2/backend/app/services/paper_mode/service.py:47` always constructs the flag with `live_blocked=True`.
- `v2/backend/app/composition/paper_mode/runtime.py:21` exposes only a clock-bound runtime closure.

### Pass: no live execution surface in paper loop

`v2/backend/app/services/paper_loop.py` remains a no-behavior placeholder. The reviewed paper-mode, paper-ledger, and evidence harness paths are typed in-memory assemblers; they do not place/cancel orders, change leverage/margin, write Redis, restart services, deploy, or enable live trading.

### Pass: paper ledger integration records risk outputs without execution

`v2/backend/app/services/paper_execution_ledger/service.py:26` records a `RiskDecisionRecord` into a `PaperExecutionLedgerEntry`. It mirrors allow/deny reasons into `record_allow` or `record_deny`, propagates lineage fields, and returns `live_blocked=True` at `v2/backend/app/services/paper_execution_ledger/service.py:80`.

The paper-mode evidence harness projects ledger entries into replay steps and summaries with the live-blocked invariant checked on every record in `v2/backend/tests/unit/paper_mode_evidence_collection_harness/test_paper_mode_evidence_collection_harness.py`.

### Blocker 1: risk gateway does not enforce the paper-mode flag

`assemble_risk_decision_record` accepts only an orchestrator decision and a clock at `v2/backend/app/services/risk_gateway/service.py:25`. It does not accept a `PaperModeFlag` or equivalent runtime-mode evidence. For `open_long` and `open_short`, it emits `risk_action="allow"` at `v2/backend/app/services/risk_gateway/service.py:49` and `v2/backend/app/services/risk_gateway/service.py:52`, then stamps `live_blocked=True` on the output at `v2/backend/app/services/risk_gateway/service.py:67`.

That proves the emitted record is non-live, but it does not prove risk approval was gated by a current, valid paper-mode runtime flag. A caller can obtain an `allow` risk decision without presenting paper-mode evidence. For the Paper Mode MVP check "risk gateway enforcement", this is a blocker.

Proposed non-live autofix task:
- Add a paper-runtime-aware risk composition/service boundary that requires a `PaperModeFlag` input before risk evaluation, validates `mode in {"paper", "live_blocked"}` and `live_blocked is True`, and denies or raises a typed service error when the flag is missing/invalid/stale. Keep this in typed in-memory code only; do not add Redis, exchange clients, schedulers, live order paths, or persistence.
- Add tests proving missing flag, false `live_blocked`, unknown mode, and stale flag cannot produce `risk_action="allow"`.

### Blocker 2: decision explainability omits paper runtime flag evidence per decision row

The paper ledger explainability envelope contains ledger/risk lineage and `live_blocked`, but it has no `paper_mode`, `paper_mode_flag_emitted_ts_ms`, or equivalent pointer to the paper runtime flag:
- Envelope fields are defined at `v2/backend/tests/unit/decision_explainability_paper_ledger_projection/harness.py:15`.
- The expected field set at `v2/backend/tests/unit/decision_explainability_paper_ledger_projection/test_decision_explainability_paper_ledger_projection.py:40` also omits runtime mode/timestamp.

The evidence harness returns the paper flag separately at `v2/backend/tests/unit/paper_mode_evidence_collection_harness/harness.py:40`, but the per-row explainability projection cannot answer which paper runtime mode/timestamp guarded a specific ledger decision. For the Paper Mode MVP check "decision explainability", this is a blocker.

Proposed non-live autofix task:
- Extend the non-live explainability harness/envelope to carry paper runtime mode and flag timestamp for each projected ledger row, sourced from a typed `PaperModeFlag`.
- Add tests proving every ledger explainability row includes `paper_mode`, `paper_mode_flag_emitted_ts_ms`, and `live_blocked=True`, and that rows cannot be projected from an invalid or absent paper flag.

## GO/NO-GO

NO-GO for Paper Mode MVP readiness until the risk gateway is explicitly gated by paper-mode evidence and decision explainability carries that runtime-mode evidence per decision/ledger row.
