# Codex Parallel Review: Paper Mode MVP

Scope: static read-only review of `v2/backend/app`, `v2/backend/tests`, and `claude_worklog/phase2_core_rebuild/paper_mode_impl`.

Disposition: BLOCKED for Paper Mode MVP readiness.

## Summary

The isolated paper-mode flag implementation is non-live and well constrained, but the MVP is not yet wired end to end. The current code can produce `PaperModeFlag(mode in {"paper", "live_blocked"}, live_blocked=True)`, and adjacent decision/risk/ledger records also hardcode `live_blocked=True`. However, the risk gateway does not require the paper-mode flag, risk approval is based only on the orchestrator decision action, the paper ledger does not record runtime mode evidence, and no integrated paper-mode pipeline proves that decisions pass through flag composition before risk and ledger recording.

## Check Results

### paper mode flag composition

PARTIAL PASS.

- `v2/backend/app/domain/paper_mode/flag.py:8-18` defines only `paper` and `live_blocked` modes plus `live_blocked`.
- `v2/backend/app/domain/paper_mode/flag.py:20-55` rejects unknown modes, invalid timestamps, and any `live_blocked` value other than `True`.
- `v2/backend/app/services/paper_mode/service.py:16-51` accepts only `paper` / `live_blocked`, invokes the supplied clock, and returns a true live-blocked flag.
- `v2/backend/app/composition/paper_mode/runtime.py:21-39` exposes a closure that forwards `requested_mode` to the assembler.

MVP gap: this flag remains an isolated runtime value. It is not consumed by the orchestrator decision, risk gateway, or paper ledger assemblers.

Residual risk: this is a static review only. I did not run live processes, Redis commands, exchange calls, or pytest.

### paper ledger integration

BLOCKED.

- `v2/backend/app/services/paper_execution_ledger/service.py:26-30` accepts only a `RiskDecisionRecord` and a clock.
- `v2/backend/app/services/paper_execution_ledger/service.py:59-78` maps risk reason codes to mirror ledger reason codes.
- `v2/backend/app/services/paper_execution_ledger/service.py:80-93` creates `PaperExecutionLedgerEntry` and hardcodes `live_blocked=True`.

Blocker: the ledger entry has no paper-mode flag input, no runtime mode field, and no `flag_emitted_ts_ms` / paper-mode evidence. A risk decision can be mirrored into the paper ledger without proving that `build_paper_mode_runtime(...).paper_mode_now(...)` was called for the same decision path.

### risk gateway enforcement

BLOCKED.

- `v2/backend/app/services/risk_gateway/service.py:25-29` accepts only an `OrchestratorDecisionRecord` and a clock.
- `v2/backend/app/services/risk_gateway/service.py:49-60` allows `open_long` and `open_short` decisions solely from the orchestrator action.
- `v2/backend/app/services/risk_gateway/service.py:67-79` creates `RiskDecisionRecord` and hardcodes `live_blocked=True`.

Blocker: the risk gateway does not require a `PaperModeFlag`, does not validate flag freshness or mode, and cannot fail closed when runtime-mode evidence is missing. The hardcoded `live_blocked=True` is a record invariant, not enforcement of paper-mode runtime composition.

### decision explainability

BLOCKED.

- `v2/backend/app/services/orchestrator_decision/service.py:105-118` preserves prediction direction, confidence, freshness, worker health, action, reason, and live-blocked status.
- `v2/backend/app/services/risk_gateway/service.py:67-79` preserves input decision action/reason.
- `v2/backend/app/services/paper_execution_ledger/service.py:80-93` preserves input risk action/reason.

Blocker: decision/risk/ledger explainability does not include runtime mode, paper-mode flag timestamp, or a proof that live execution was blocked by the paper-mode runtime flag. The current explanation chain can justify model/risk decisions but not why the path was paper-only.

## Concrete Blockers

1. Risk gateway approval does not depend on paper-mode flag evidence.
2. Paper ledger recording does not include runtime mode or paper-mode flag lineage.
3. No integrated non-live composition path proves `paper_mode_now -> orchestrator decision -> risk gateway -> paper ledger`.
4. No negative tests prove missing, invalid, stale, or non-paper runtime-mode evidence blocks risk approval or ledger recording.
5. Decision explainability lacks paper-mode runtime evidence.

## Proposed Non-Live Autofix Tasks

1. Add a non-live `PaperModeFlag` dependency to the risk-gateway service/composition boundary, or introduce a dedicated paper risk wrapper that requires it before any allow decision can be produced.
2. Extend risk and/or ledger records with explicit runtime-mode evidence fields such as `paper_mode`, `paper_mode_flag_emitted_ts_ms`, and `paper_mode_live_blocked`, preserving existing no-live invariants.
3. Add a paper-mode MVP composition harness that assembles the flag, orchestrator decision, risk decision, and paper ledger entry in one in-memory path with no Redis, exchange, scheduler, or persistence side effects.
4. Add negative unit tests for absent/non-`PaperModeFlag` runtime evidence and for any stale/unsupported mode policy chosen by the implementation.
5. Add explainability assertions proving the final decision/risk/ledger output can show the runtime mode and live-blocked paper-mode flag that governed the path.
