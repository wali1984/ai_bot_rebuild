# Codex Parallel Review: Paper Mode MVP

Review mode: read-only inspection only. No files were modified, no Redis access was performed, no services were restarted, and no live actions were taken.

## Verdict

BLOCKED.

The paper-mode flag itself is well-scoped and non-live, but the MVP is not yet enforceably wired through the risk and ledger path. Current code can assemble risk decisions and paper ledger entries without receiving or recording a `PaperModeFlag`, so paper mode is not a required precondition for risk approval or ledger recording.

## Checks

### Paper mode flag composition

PASS with scope caveat.

- `v2/backend/app/domain/paper_mode/flag.py:8-18` defines only `paper` and `live_blocked` modes and carries `live_blocked`.
- `v2/backend/app/domain/paper_mode/flag.py:20-55` rejects unknown modes, invalid timestamps, and `live_blocked != True`.
- `v2/backend/app/services/paper_mode/service.py:16-51` only accepts the two allowed requested modes and always returns `live_blocked=True`.
- `v2/backend/app/composition/paper_mode/runtime.py:21-39` captures a clock and returns a runtime closure without I/O.

### No live execution

PASS.

- `v2/backend/app/services/execution_router.py` is a placeholder stating live order calls remain blocked until a later milestone.
- `v2/backend/app/services/paper_loop.py` is a behaviorless placeholder.
- The inspected paper-mode, risk-gateway, paper-ledger, and replay composition code is pure assembler/domain code; no exchange adapter calls, order placement, leverage/margin changes, deployment hooks, service restarts, or Redis writes were observed.

### Paper ledger integration

BLOCKED.

`v2/backend/app/services/paper_execution_ledger/service.py:26-93` assembles a `PaperExecutionLedgerEntry` from a `RiskDecisionRecord` and sets `live_blocked=True`, but it does not require a `PaperModeFlag` input and does not record the mode or flag timestamp. `v2/backend/app/composition/paper_execution_ledger/runtime.py:15-27` exposes the same gap at the composition boundary.

The evidence harness links paper-mode flag creation to replay evidence in `v2/backend/tests/unit/paper_mode_evidence_collection_harness/harness.py:30-62`, but it starts from prebuilt ledger entries. It does not prove that a paper flag is required before risk decisions or ledger entries are produced.

### Risk gateway enforcement

BLOCKED.

`v2/backend/app/services/risk_gateway/service.py:25-79` accepts only an `OrchestratorDecisionRecord` and clock. Open-long/open-short decisions become `allow` at `v2/backend/app/services/risk_gateway/service.py:49-54`, and the output hard-codes `live_blocked=True` at `v2/backend/app/services/risk_gateway/service.py:67-79`.

`v2/backend/app/composition/risk_gateway/runtime.py:15-27` also has no `PaperModeFlag` dependency. Missing, stale, invalid, or non-live-blocked paper-mode evidence cannot deny risk approval because it is not part of the risk gateway contract.

### Decision explainability

BLOCKED.

`v2/backend/app/proof/non_live_operational_proof.py:269-279` emits decision explainability rows, and `v2/backend/tests/unit/proof/test_non_live_operational_proof_artifacts.py:64-88` verifies lineage fields. However, the required lineage set includes `live_gate_status` but not `paper_mode`, `paper_mode_flag_emitted_ts_ms`, or any paper-mode flag id/evidence field.

This means an operator can see that the proof is non-live, but cannot trace whether a specific decision was made under a valid paper-mode flag.

## Concrete Blockers

1. Risk gateway does not require paper-mode evidence.
   - Add a non-live autofix task to extend the risk gateway service/composition contract with a `paper_mode_flag: PaperModeFlag` keyword-only input.
   - Deny or raise before approval when the flag is missing, invalid, not `paper`, not `live_blocked`, or has `live_blocked != True`.
   - Add unit tests proving open-long/open-short cannot become `allow` without valid paper-mode evidence.

2. Paper ledger does not require or record paper-mode evidence.
   - Add a non-live autofix task to extend paper ledger assembly with `paper_mode_flag: PaperModeFlag`.
   - Propagate `paper_mode` and `paper_mode_flag_emitted_ts_ms` into the ledger entry or an explicit evidence wrapper.
   - Add tests proving ledger recording rejects missing or invalid paper-mode evidence.

3. Decision explainability omits paper-mode evidence.
   - Add a non-live autofix task to include paper mode and live-blocked posture in risk, ledger, replay, and explainability payloads.
   - Add tests proving every operator-visible explanation contains the runtime mode and live-blocked status for the decision being explained.

4. Current evidence harness proves adjacent surfaces, not end-to-end enforcement.
   - Add a non-live integration harness that composes paper mode -> orchestrator decision -> risk gateway -> paper ledger -> replay/explainability.
   - Include negative cases for missing flag, unknown mode, `live_blocked=False`, and stale/mismatched flag timestamp.
   - Keep the harness deterministic and local-only; no Redis, no exchange adapters, no live services.

## Proposed Non-Live Autofix Tasks

- `paper_mode_risk_gateway_flag_required_autofix`: require `PaperModeFlag` in risk gateway service and composition, with deny/raise tests for missing or invalid flag evidence.
- `paper_mode_ledger_flag_lineage_autofix`: require and propagate paper-mode evidence into paper ledger records or a typed evidence envelope.
- `paper_mode_explainability_runtime_evidence_autofix`: add paper-mode fields to operator-visible proof and explainability payloads.
- `paper_mode_end_to_end_non_live_contract_autofix`: add deterministic integration tests across paper mode, risk gateway, ledger, replay, and explainability without live side effects.
