# Codex Parallel Review: Paper Mode MVP

Review mode: static/read-only inspection, except for writing this requested artifact and the paired GO/NO-GO marker. No Redis, live service, exchange, leverage/margin, deployment, or order action was performed.

## Verdict

BLOCKED.

The paper-mode components are individually pure and live-blocked, but the MVP is not ready because the paper-mode flag is not part of the risk-gateway or paper-ledger enforcement path. A caller can build a risk decision and paper ledger entry without presenting a `PaperModeFlag`; those services synthesize `live_blocked=True` internally rather than enforcing a composed runtime-mode precondition.

## Evidence Reviewed

- `v2/backend/app/domain/paper_mode/flag.py:8-55` defines only `paper` and `live_blocked` modes and rejects `live_blocked != True`.
- `v2/backend/app/services/paper_mode/service.py:13-51` accepts only `paper` / `live_blocked`, rejects other requested modes before creating a flag, and constructs `PaperModeFlag(..., live_blocked=True)`.
- `v2/backend/app/composition/paper_mode/runtime.py:21-39` exposes a pure closure-based composition root for the flag.
- `v2/backend/app/services/risk_gateway/service.py:25-79` converts open-long/open-short orchestrator decisions into `allow` risk decisions and sets `live_blocked=True` internally.
- `v2/backend/app/composition/risk_gateway/runtime.py:15-27` builds a risk evaluator that accepts only `decision`; it has no paper-mode/runtime flag input.
- `v2/backend/app/services/paper_execution_ledger/service.py:26-93` mirrors risk decisions into paper ledger entries and sets `live_blocked=True` internally.
- `v2/backend/app/composition/paper_execution_ledger/runtime.py:15-27` builds a ledger recorder that accepts only `decision`; it has no paper-mode/runtime flag input.
- `v2/backend/app/services/execution_router.py` and `v2/backend/app/services/paper_loop.py` remain placeholders, so no live execution route was found in the paper-mode path.
- Decision explainability test harnesses project `live_blocked`, and the data-contract harness projects `paper_mode_mode` / `paper_mode_live_blocked`, but those are test-side envelopes rather than enforcement at the risk or ledger boundary.

## Checks

### Paper Mode Flag Composition

PASS at the isolated flag boundary. The domain object and service reject non-paper/non-live-blocked modes and require `live_blocked=True`. The composition root captures the injected clock and forwards requested mode to the service without I/O or live behavior.

### No Live Execution

PASS for the inspected paper-mode implementation. The paper-loop and execution-router files are placeholders, exchange adapter packages are effectively empty scaffolds, and no order placement/cancel/leverage/margin mutation path was found in the paper-mode, risk-gateway, or paper-ledger services.

### Paper Ledger Integration

PARTIAL. The paper ledger service mirrors `RiskDecisionRecord` into `PaperExecutionLedgerEntry` with lineage fields and reason-code mapping. However, it does not require evidence that the risk decision came from an active paper-mode runtime flag. It trusts the input `RiskDecisionRecord` and unconditionally emits `live_blocked=True`.

### Risk Gateway Enforcement

BLOCKER. The risk gateway allows open-long/open-short orchestrator decisions solely from `OrchestratorDecisionRecord.decision_action`. It does not accept `PaperModeFlag`, does not validate `mode`, does not validate flag freshness, and cannot deny when paper-mode evidence is missing. This leaves the typed paper-mode flag adjacent to the decision path rather than enforcing the decision path.

### Decision Explainability

PARTIAL. Existing explainability harnesses preserve decision/risk/ledger reason codes and live-blocked state, and the data-contract harness includes paper-mode fields. The enforcement gap remains visible here too: explainability can project a separately built paper-mode flag, but the risk and ledger records do not carry a paper-mode flag id/timestamp/mode source or prove they were gated by it.

## Concrete Blockers

1. Missing paper-mode precondition in risk gateway.
   - Current surface: `assemble_risk_decision_record(decision, now_ms_clock)`.
   - Required for MVP readiness: a non-live risk evaluation path must require a valid `PaperModeFlag` or a composed paper-runtime guard before allowing any `allow` risk action.

2. Missing paper-mode precondition in paper ledger recorder.
   - Current surface: `assemble_paper_execution_ledger_entry(decision, now_ms_clock)`.
   - Required for MVP readiness: ledger recording must either consume a risk record already proven paper-gated or require the paper-mode flag directly and fail closed when missing/invalid.

3. Missing negative integration tests for absent/invalid paper-mode evidence.
   - Existing tests assert each layer returns `live_blocked=True`, but they do not prove missing/stale/invalid paper-mode evidence blocks risk approval or ledger recording.

4. Explainability is not tied to enforcement.
   - Test harnesses can project paper-mode fields, but risk/ledger records do not expose a causal paper-mode enforcement field such as `input_paper_mode`, `input_paper_mode_live_blocked`, or `input_paper_mode_flag_ts_ms`.

## Proposed Non-Live Autofix Tasks

1. Add a pure paper-mode guarded risk evaluator in `v2/backend/app/composition/risk_gateway/` or a new narrow paper-session composition module. It should require `paper_mode_flag: PaperModeFlag` plus `decision`, reject missing/non-flag/stale/`live_blocked=False`/unknown mode, and only then call the existing risk assembler.

2. Add unit tests proving risk evaluation fails closed when paper-mode evidence is absent, not a `PaperModeFlag`, has an unsupported mode, has `live_blocked=False`, or is stale by an injected max-age threshold.

3. Add a pure guarded paper-ledger recorder that either requires the guarded risk result type or accepts `paper_mode_flag` and refuses to record without valid paper-mode evidence. Keep it in-memory and return-only; do not add Redis, files, SQL, schedulers, or background loops.

4. Extend non-live explainability projection tests to assert the same paper-mode evidence that gated risk/ledger is present in the emitted explanation envelope.

5. Add an end-to-end pure unit test for `paper_mode_flag -> orchestrator decision -> guarded risk decision -> guarded paper ledger entry`, with open-long/open-short and deny cases, and with a negative test showing the same decision is blocked when the paper-mode flag is omitted.
