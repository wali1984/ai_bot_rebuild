## Gap statement

Prior to this update, two architecture-tier control documents were skeletal and disconnected from the four prior remediation closures (`12A`–`12D`):

- `claude_worklog/v2_architecture/17_IMPLEMENTATION_SEQUENCE_AND_MILESTONES.md` was a 26-line list. It named the A–O sequence and added a one-line "Milestone gating" stanza, but did not enumerate the objective gate evidence that the supervisor must verify before milestone B (scaffold) may begin, did not define the per-milestone validation artifact catalog, did not bind the L0–L5 governance taxonomy from `13_AUDIT_LEDGER_AND_AI_CHANGE_GOVERNANCE.md` to the milestones, and did not state the live readiness preconditions in a single auditable place.
- `claude_worklog/v2_architecture/18_ARCHITECTURE_REVIEW_GO_NO_GO.md` was a single line `V2_ARCHITECTURE_READY_FOR_CLAUDE_CODEX_REVIEW`. It did not name the resolved blockers, did not name the remaining preconditions for build-ready status, did not point at the closure files, did not name the next required action (Codex adversarial rerun on the post-remediation set), and did not explicitly distinguish "ready for review" from "ready to build". The downstream Codex rerun in `claude_worklog/v2_architecture_codex_review/16_ACTUAL_CODEX_RERUN_GO_NO_GO.md` had returned `ACTUAL_CODEX_ARCHITECTURE_RERUN_FAIL` against the pre-12A architecture set, but `18` did not surface this fact or the path to vacate it.

The result was that even though `12A`–`12D` had each individually closed their architecture gaps, the V2 build supervisor had no single document that named the integrated gate-evidence requirement before scaffold planning could legitimately begin. A future supervisor task could read `18`'s prior single line and incorrectly conclude that the architecture was approved for V2 scaffold.

## Why this closes the gap

- **Scaffold planning is rejectable, not advisory.** The §3 table in `17` makes the entry condition for milestone B objective. A supervisor reading the table cannot mistake the four architecture-text closures for sufficient authorization. Item 5 (Codex rerun PASS) is required and currently OPEN; the supervisor refuses milestone B until it flips.
- **Each milestone has a single named validation artifact.** The §6 catalog forbids milestones from self-declaring completion via prose. A milestone is complete only when its `<LABEL>_*_VALIDATION.md` exists with empty `missing_evidence[]` and the gate_evidence_ref it cites resolves.
- **Governance level cannot be self-elevated.** §7 binds the L0–L5 taxonomy to specific milestone classes; an L4-rated change (e.g., paper→live switch) cannot be slipped through under L2 review. The audit-ledger entry hash is required for L4/L5 dependencies.
- **Live readiness is single-sourced.** §8 of `17` reproduces all seven preconditions in one place, mirroring the §7 gate-metric formula in `14_CONTINUOUS_MONITORING_AND_EVIDENCE_PACKET_ARCHITECTURE.md`. A decision to activate live cannot point at `17` alone; it must satisfy every listed condition and carry an L5 audit-ledger entry.
- **`18` is now operationally unambiguous.** The first line is still grep-friendly (`ARCHITECTURE_READY_FOR_CODEX_RERUN`), but the body documents the decision scope, the blockers it does not vacate, the next required action, and the things it does NOT authorize. A supervisor or operator reading the file cannot conclude that V2 build is approved.
- **Codex rerun is the next mandatory step.** The path forward is named: supervisor task `010_actual_codex_architecture_rerun_after_remediation` consumes the four closures, updates `15_ACTUAL_CODEX_RERUN_AFTER_REMEDIATION.md`, and either flips `16_ACTUAL_CODEX_RERUN_GO_NO_GO.md` to PASS or enumerates new blockers. Either outcome advances the system toward auditable build-readiness without bypassing review.
- **The architecture text is fully testable.** Every gate condition, validation artifact, governance level, and live precondition maps to either a file path, an audit-ledger entry, a closure document, or a `liveness_confidence_level` value. A future supervisor implementation that fails any of them cannot claim this gap is closed.
